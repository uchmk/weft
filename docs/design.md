# weft の設計

Markdown 専用エディター weft の設計。2026-11-02 の設計メモ（`~/.claude/plans/abundant-weaving-candy.md`）を写し、
ito v0.221.1（rev `73cce5b`）で済んだ所を直した。以後はこのファイルを正とする。

## Context
kura で `.md` に Enter を押したときに入る、Markdown 専用のエディターを作る。fude（1 行で打つ執筆用）とは別物。
狙いは 3 つ全部: (1) 読んで整える、(2) 見出し・リスト・表をキーで組み替える、(3) フォルダ（vault）を扱う。
競合（Obsidian、Typora など）が弱い「キーだけで構造を操作し、日本語入力にも強い」所を狙う。

## 決めたこと
- **別アプリ**として作る（`/new-app` の雛形）。kura は拡張子 `md` の opener として呼ぶだけ。単体でも起動できる。
- **Markdown 限定。** マクロ・拡張機能・Vim 風のモード・レジスタは作らない。汎用の編集は 1 キーで `$EDITOR` へ渡す（ito-openin）。
- 編集の操作は**すべて名前つきコマンド**にする。キー割り当ては設定ファイル（ito-keys / ito-keymap）で変えられる。コマンドの列を 1 つの名前にまとめる所までは持つ（スクリプト言語は持たない）。
- 設定ファイル（TOML など）は構文エラーの表示だけ。ログを読む機能は kura 側（follow、色分け、絞り込み。ito-tail あり）。

## 要件（ユーザー追加分）
**1. キーボードファーストの構造操作（2 の中身。マウス不要）**
- ブロック単位の上下スワップ: 段落、リスト項目、見出し（子の階層ごと）を、ショートカット 1 発で上へ・下へ。
- スマート・インデント: リスト項目の階層の上げ下げ、タスクの完了・未完了のトグル、番号付きリストの自動振り直し。
- 表の自動整形: セル内を Tab / Shift+Tab で移動し、入力文字数に応じて列幅と区切り線（`|---|`）をその場で整える（全角は 2 セル幅。kura の `str_width` が使える）。

**2. 日本語・IME に特化した挙動**
- 変換中・確定時にカーソルが飛ばない、選択が解除されない安定した処理（ito-ime が土台。確定の前後でカーソルと選択を保つ）。
- 全角スペースと、意図しないハード改行を、控えめかつ明確にハイライトする（Markdown のレイアウト崩れの原因になるため）。

**3. リンク・パス補完（vault 層の入口）**
- Wiki リンク `[[…]]` の高速インクリメンタル補完: `[[` を打った瞬間にポップアップで、vault 内のファイル名と見出しを絞り込んでリンク化（ito-match、ito-palette、必要なら ito-store の索引）。
- 画像・ファイルのパス補完: 画像の貼り付けやリンク挿入で、vault 内のフォルダ構造から相対パスを解決して挿入する。

**4. 割り切り（シングルタスク）**
- 「書く・整える」に特化する。プラグインの仕組みも、複雑な WYSIWYG も持たない。汎用の編集は 1 キーで `$EDITOR` へ。
- 開いた瞬間に書けて、構造が整う軽さを保つ。起動の速さを機能の優先度より上に置く。

**5. デザイン**
- モダンな見た目にする（ito-theme のテーマ、ito-fonts のフォントに乗る）。
- ボタンは**アイコン＋メッセージ**（文字）の組にする。アイコンが ito に無ければ、アプリに独自に描かず ito にアイコンを足す（crate-request）。
- ツールバーやボタンの項目は、すべて名前つきコマンドの一覧（ito-palette）と同じ元から出す。

## Markdown 特化なら他に要る機能（優先度つき）
**必須（最初の版に入れる）**
- 貼り付けの賢さ: 選択範囲に URL を貼ると `[選択](URL)` にする。画像を貼ると添付フォルダーに保存して相対パスで挿入する。Web や Excel からの表・HTML を Markdown に直す。
- 検索と置換（ito-match。正規表現・あいまい）、現在のファイル内と vault 全体。
- 見出しの折りたたみ（節ごと）と、目次の挿入・更新。
- YAML フロントマターの扱い（タイトル・日付・タグの編集、色づけ）。
- 保存まわり: 自動保存、強制終了からの復元、外部で変更されたときの検知（ito-watch）、UTF-8・BOM・CRLF を保つ。
- 字数（日本語の文字数）、選択範囲の字数。

**あると強い（vault 層と一緒に）**
- リンク切れ・画像切れのチェック（lint の一部）。ファイル名を変えたら、vault 内のリンクを追従して直す。
- タスクの一覧（vault 全体の未完了を集める）、タグの一覧。
- 日付ノート・テンプレート（マクロではなく、ひな形ファイルの挿入）。
- 脚注と参照リンクの整理（番号の振り直し、未使用の定義の検出）。
- 日本語の文章の lint: 全角と半角の間のスペース、句読点の統一、全角スペースの検出（可視化とセット）。
- 書き出し: HTML・PDF・PNG と、リッチテキストとしてコピー（ito-export）、印刷。
- 整形プレビューでの画像表示（kura の #490 と同じ作りに揃える）。

**後回し／作らない**
- 数式と図の**編集補助**（数式パレット、図のドラッグ編集）: 作らない。表示は下の「数式と図」で対応する。
- 共同編集、同期、クラウド連携: **後で決める**（当面はフォルダーと Git に任せる。設計では、ファイルの読み書きと変更の検知を 1 か所に集めておき、後から足せる形にする）。
- プラグイン、テーマ職人向けの CSS: 作らない。

## 画像・動画の貼り付け（定義）
**画像**
- 貼り付け（クリップボードの画像、またはファイルのドロップ・貼り付け）→ 添付フォルダーへ **WebP に圧縮して保存** → 相対パスの `![](…)` を挿入。
- 添付フォルダー: 既定はそのノートと同じ場所の `assets/`（設定で変更可）。ファイル名は日時＋連番（`20261102-1530-1.webp`）。同名は上書きしない。
- 圧縮: 品質は設定（既定は非可逆 80 前後）。最大幅の上限（例: 2000px）を超えたら縮小。**WebP や GIF（アニメ）は再圧縮しない**（アニメ GIF は WebP にせずそのまま保存）。元の画像を残すか捨てるかも設定。
- 注意（要確認）: Rust の `image` クレートの WebP 出力は可逆のみで、非可逆には `libwebp`（C ライブラリ、`webp` クレートなど）が要る。ito や kura が既に画像処理で何を使っているかを調べてから決める。ito に画像の変換クレートが無ければ crate-request。
- 取り消し: 貼り付けは 1 回の「元に戻す」で、挿入と保存したファイルの両方を戻す（ファイルはゴミ箱へ）。

**動画**
- Markdown に標準の動画構文は無い。挿入は、既定では `![](clip.mp4)` ではなく**リンクとして** `[clip.mp4](assets/clip.mp4)`、設定で `<video src="assets/clip.mp4" controls></video>`（GitHub 系で通る形）に切り替える。
- 貼り付け・ドロップした動画ファイルは添付フォルダーへ**コピーするだけ**（再圧縮はしない）。`ffmpeg` があれば、任意で MP4 への変換・圧縮ができるようにする（無ければ項目を出さない）。
- プレビュー: egui で動画を再生するのは重いので、**1 コマ目のサムネイル＋再生マーク**を出し、Enter で既定のプレーヤーで開く（ito-openin）。アプリ内の再生は後回し。サムネイルは `ffmpeg` か、Windows のシェルのサムネイルで作る（kura のプレビューが使っている仕組みに合わせる）。
- 対応は段階的に: (a) ファイルのコピーとリンク挿入、(b) サムネイル、(c) アプリ内再生（作るかは後で判断）。

## 追加要件その 2（リンク管理、データ保護、日本語整形、外部連携）
**リンク・ファイル管理（vault 層）**
- リネーム・移動への追従: vault 内でファイルの名前を変える・動かすと、それを指す `[[Wikiリンク]]` と相対パスのリンク（画像も）を、他の Markdown ごと一括で書き換える。実行前に「何ファイルの何か所を変えるか」の一覧を見せ、1 回の操作で元に戻せる（変えた全ファイルをスナップショットに入れる）。
- リンクのホバープレビュー: リンクにカーソルを置く、または Ctrl を押すと、リンク先の冒頭数行と見出しの構造をフローティングで出す（kura のミニマップのホバーカードと同じ作り方）。

**データ保護**
- ガターの変更表示: 行番号の脇に、保存済み（またはコミット済み）の内容と比べて追加・変更・削除された行を色で出す。比較は ito-diff（`diff_lines`）。コミットとの比較は Git の読み取りだけ（書き込みはしない）。
- スナップショットの世代管理: 数分おき・保存のたびに、隠しフォルダー（vault 直下の `.snapshots/` など）に履歴を溜め、一覧から差分を見て復元できる。世代数と期間に上限を持つ（古いものから消す）。自動保存・強制終了からの復元と同じ仕組みに載せる。

**日本語・テキストの整形（設定ファイルで ON/OFF、既定は OFF）**
- 半角・全角の揺れ、スマートクォート、句読点を、ルールに従って直すコマンド（一発で整える）と、保存時に自動で直す設定。規則は設定ファイルに書き、直す前に差分を見せられる。
- 見出しの自動ナンバリング: `1.` / `1.1` / `(1)` などを表示だけで付ける（ファイルには書かない）か、ファイルへ書き込む（一括の付け直し）かを選べる。
- 構造コマンドの拡張: 節の階層を一括で繰り下げ・繰り上げ（子孫の見出しも一緒に）、節を選んで丸ごと別の節の下へ移す。マルチカーソルや矩形選択は作らない。

**外部エディターとの往復**
- `$EDITOR`（Cursor、VS Code など）を、**カーソル位置（行・列）と選択範囲**を引き継いで一発起動し、編集が終わったら、変更をこのエディターが読み直して戻る（ito-watch で検知。未保存の変更があれば先に保存する）。
- 行番号を渡す書式は kura の `[line_args]` の仕組みに揃える（ito-openin の拡張。列まで渡せない外部エディターは行だけ）。バイト位置は、外部エディターが受け取れる形（行・列）に変換して渡す。

## 数式（KaTeX）と図（Mermaid）の表示
- 書式: インライン `$…$`、ブロック `$$…$$`、コードフェンス ` ```math `（GitHub 互換）。図は ` ```mermaid `。pulldown-cmark の `ENABLE_MATH` で数式の範囲が取れる（要確認）。
- 方針: どちらも**SVG にして、既存の SVG→ラスター変換（ito-export の resvg）で画像として整形プレビューに出す**。kura の #490（プレビューに画像を描く）と同じ仕組みに乗せ、結果はキャッシュする（ソースの内容が変わったときだけ描き直す）。ワーカースレッドで描いて、UI を止めない。
- 原文側（編集中）は、数式も図も**ソースのまま**色づけする。プレビューにだけ描く。エラー時は、プレビュー側にエラー文と該当の行を出し、前回成功した絵は残さない。
- 実装の候補（どれも**要確認。採用前に実物で試す**）:
  - 数式: Rust の LaTeX→MathML／SVG のクレート（`pulldown-latex`、`mathjax_svg` など）、または KaTeX を JS ランタイム（`rquickjs` など）で動かす。KaTeX の HTML 出力は egui で組むのが難しいので、SVG か MathML 経由を優先する。
  - Mermaid: Rust 製の描画（`mermaid-rs-renderer` など。対応する図の種類が限られる可能性）、または mermaid.js を JS ランタイムで動かす（DOM が要り、重い）、または ヘッドレスブラウザ（重いので避ける）。**対応する図の種類**（flowchart、sequence、class、state、gantt、er など）を試して、足りない種類は元のコードを表示する。
- 色: アプリのテーマ（ito-theme）の色を渡し、ライト・ダークで読めるようにする。
- 書き出し（HTML・PDF）では、同じ SVG をそのまま埋め込む。
- 時期: 数式は v2、Mermaid は v2〜v3（画像表示の共通化とライブラリの選定が済んでから）。ライブラリの選定は ito に置く crate-request の候補（kura のプレビューでも使えるため）。

## 大きなファイル・巨大な vault（v1 の土台の段階で決める）
kura が既にやっていること（README「Scrolling the preview」）: 画面に出る行だけを描く（`ScrollArea` は使わず、行数を測らない）、プレビューは先頭 `max_text_bytes`（256 KiB）だけ読む、`big_text_bytes`（8 MiB）以上は背景で行の索引を作り、Seek + Read で見える行だけ読む。末尾に追記されるログは続きから索引する。ミニマップの行は 1 行 6 バイトでワーカーが作る。
これを編集用に引き継ぐ。**メインスレッドでは、パース・色づけ・差分・索引を一切計算しない。**

- **3 つの段階**（サイズで自動に切り替え。境目は設定にする）:
  1. 通常（約 1 MiB まで）: ファイル全体を編集できる。構造木・色づけ・目次・ミニマップ・ガターの差分を、すべてワーカーで作る。
  2. 大きい（1〜8 MiB）: 編集できるが、色づけは**見えている範囲と前後だけ**、構造木と目次は背景で段階的に作る（できた分から出す）。整形プレビューは見えている節だけ。
  3. 巨大（8 MiB 以上、`big_text_bytes` に合わせる）: 行の索引による**読み取り中心**。編集は、開いた場所の周りだけ可能にするか、`$EDITOR` へ渡す（1 キー）。どちらにするかは実装時に決める。
- **バッファ**: 行の途中への挿入・削除が大きなファイルでも速い構造（rope など）。実装は ito や kura が何を使っているか調べてから決める（アプリに先に独自の型を作らない）。
- **ワーカーとの受け渡し**: 編集のたびに「版番号つき」の依頼をワーカーに出す。古い版の結果は捨てる。ワーカーが追いつくまで、画面は**前の結果の色のまま**文字だけ新しく出す（色が一瞬ずれるのは許す。入力は絶対に待たせない）。入力が続く間は、ワーカーの依頼をまとめる（デバウンス）。
- **色づけ**: 大きなファイルでは「N 行ごとの状態の保存点」が要る。ito-syntax の `Stream` は v0.221.0 で `Clone` になった（uchmk/ito#4）ので、N 行ごとに複製して保存点にする。
- **ガターの差分**: 保存済みの内容との比較を、変更された範囲の周りだけ計算する。巨大では出さない。
- **vault 側**: 索引（見出し、リンク、全文）は初回だけ背景で作り、あとは変更のあったファイルだけ更新する（ito-watch、ito-store）。千〜数万ファイルでも起動を待たせない。
- **テスト**: 数十万行の `.md` と 1 万ファイルの vault を作るスクリプトを用意し、`--keys` で「開く→末尾へ移動→入力→保存」を計測する（入力から画面更新までの時間に上限を決める）。

## エッジケース（最初から設計に入れる）
- **IME と補完ポップアップ**: `[[` や `/` による補完は、**IME の変換中（コンポジション中）は出さない・確定の Enter を補完の決定に使わない**。キー入力の優先順位は「IME → 補完ポップアップ → キーマップ」とし、ito-ime のイベントと分離して決める。ローマ字入力の途中で `[[` が出来ても、確定するまで補完を開かない。確定後に直前の文字から判断して開く。
- **改行コード・BOM・文字コード**: 読んだときの改行（CRLF / LF / 混在）と BOM の有無をバッファのメタデータに持ち、**保存時は元のまま書き戻す**。新規ファイルの既定は設定（既定は LF・BOM なし）。混在のファイルは、勝手に揃えず、状態を表示して「揃える」コマンドを別に用意する。UTF-8 以外（Shift_JIS など）は、検出したら警告して読み取り専用で開くか変換を選ばせる。
- **ファイルのロックと外部変更**: 他のプロセスが掴んでいて開けない・書けないときは、理由を表示し、読み取り専用で開くか、一時ファイルに保存して後で置き換える。保存は**一時ファイルに書いてから置き換える**（途中で落ちても元が壊れない）。外部で変更されたら、未保存の変更があるときは差分を見せて選ばせる（ito-watch）。
- **添付ファイルの掃除**: 画像を貼っては消す運用で `assets/` に参照されないファイルが溜まる。vault 層とリンク切れのチェックの一部として、**どこからも参照されていない添付ファイルを一覧にして、確認のうえで削除（ゴミ箱へ）するコマンド**を用意する。同じ内容の画像の重複保存は、貼り付け時にハッシュで検出して既存を再利用する。リネーム追従と同じ「参照の索引」を使う。

## 範囲の確認（作る前に切る）→ 5 つのフェーズ（外部レビューを受けて改訂）
最初の案の v1 は大きすぎた（画像、IME、外部変更検知、2 画面、ミニマップ、巨大ファイルを同時にやる形）。**編集エンジンと構造コマンドを先に極め、周りは後から足す**順にする。
- **フェーズ 1 編集エンジン**: バッファ、カーソル、選択、元に戻す・やり直す、Markdown の構造木（バイト範囲つき）、構造コマンドの土台、コマンドとキーマップ。
- **フェーズ 2 日本語特化**: ito-ime の統合、IME と補完のイベント分離、全角スペースとハード改行の可視化、日本語の文字数、カーソル・選択の安定。
- **フェーズ 3 Markdown 操作**: ブロック移動、節の移動・昇格・降格、リストの階層操作、タスク切り替え、表の編集と整形、見出しの折りたたみ、構造選択・構造ナビゲーション・構造を壊さない削除。
- **フェーズ 4 実用エディター**: 自動保存と復元、外部変更の検知、画像貼り付け（WebP）、右側プレビュー、目次・ミニマップ、ガターの差分、外部エディター連携、巨大ファイルの段階（ワーカー分離は**フェーズ 1 から設計に入れる**。実装の仕上げがここ）。
- **フェーズ 5 vault**: Wiki リンクと補完、バックリンク、全文検索、リネーム追従、スナップショット、添付の掃除、ホバープレビュー。
- その後: 数式・Mermaid、書き出し、動画、テンプレート、タスク・タグの一覧、日本語の整形ルール、見出しのナンバリング、ライブプレビューの判断。
- フェーズ 1〜3 が済んだ時点で、既存のエディターと違う価値を持つ。ここまでを最初の目標にする。

## 設計原則（7 つ。判断に迷ったらここへ戻る）
1. Markdown が主役。汎用テキストエディターにはならない。
2. キーボードだけで完結する。マウスは補助。
3. 操作はすべて名前つきコマンド。
4. 日本語 IME を最優先に考える。
5. 編集操作は構造を理解する。
6. 入力を絶対に待たせない。
7. ito・kura の資産を最大限再利用する（ito-first）。

## 構造のレビューで取り入れる設計（外部レビューより）
**コマンドと層**
- コマンドは UI に依存しない。キー、コマンドパレット、ツールバー、テスト、将来の自動操作から**同じコマンド**を呼ぶ。ツールバーは一覧から生成する。
- 名前は `block.move_up`、`section.promote`、`list.toggle_task`、`table.format`、`table.next_cell`、`heading.fold`、`heading.insert_toc` のように「対象.動作」で揃える。
- 層は次のとおり: UI（エディター、プレビュー、目次、ミニマップ）／コマンド（ブロック、節、リスト、表）／**Document Engine**（バッファ、カーソル、選択、元に戻す、構造木、ソース範囲）／ファイル（保存、復元、監視、スナップショット）／vault（索引、リンク、検索、添付）。**Document Engine が心臓部**で、UI を持たず、単体でテストできる形にする。

**トランザクション**
- 1 回の操作は 1 回の元に戻すで完全に戻せる。画像の貼り付けなら、バッファへの挿入、`assets/` へのファイル作成、元に戻す履歴の登録を**1 つのトランザクション**にする（元に戻すと、挿入した Markdown を消し、作ったファイルをゴミ箱へ）。節の移動、複数ファイルのリンク修正、リネームも同じ。
- ファイルへの作用（作成・移動・削除）は、トランザクションに「逆操作」を持たせて実行する。

**位置の扱い**
- 構造解析は**バイト範囲**、カーソルは**文字境界（Unicode スカラー値、書記素クラスタも考慮）**。日本語・絵文字・全角・CRLF で一致しないため、変換を 1 か所（Document Engine の位置モジュール）に集め、他では変換しない。

**入力の優先順位（絶対に崩さない）**
- キー入力 → IME の変換中なら IME へ → 補完ポップアップが開いていればポップアップへ → キーマップ → 名前つきコマンド。変換中の Enter は確定であってコマンドではない。

**入力経路の約束**
- 入力から画面更新までの経路に、Markdown 全文の再解析を入れない。解析はワーカーで版番号つきに行い、編集は先に画面へ反映する。

**追加する構造機能（フェーズ 3）**
- 構造選択: 現在の単語 → 段落 → リスト → 見出しの配下 → 親の見出しの配下、とコマンドを繰り返すたびに広げる（Vim のテキストオブジェクトの模倣ではない）。
- 構造を壊さない削除: 見出しだけ消す／節ごと消す／見出しを段落にする／子の見出しを 1 段繰り上げて残す。
- 構造診断（lint）: 見出し階層の飛び、空の見出し、リストのインデントの不揃い、表の列数、リンク先の欠け、見出しの重複。自動修正は必ず差分を見せてから。
- 構造ナビゲーション: 次・前の見出し／リスト／表／コードブロック／未完了タスク、親の節、子の節。
- 集中表示: 現在の節だけを表示して他を隠す（文書は変えない）。

**画面**
- 3 領域: 左に原文＋ミニマップ、中央に整形プレビュー、右に目次・構造ナビ（必要なときだけ）。下部の状態欄に、行・列、日本語の文字数、選択の文字数、保存状態、文字コード、改行コード、IME の状態。ライブプレビューは初期は作らない。

**進め方**
- 新しいアプリを作り始める前に、ito に何を切り出すかを決める。順序: (1) ito の既存クレートと kura の実装を調べる（済）→ (2) 構造木とバイト範囲の共通 API を設計（見出し側は `ito-outline` で済み。リスト・表・節の移動が残り） → (3) 編集バッファと元に戻すの再利用可否を確認 → (4) コマンドエンジンを設計 → (5) crate-request をまとめる → (6) `/new-app` → (7) フェーズ 1 を実装 → (8) kura の opener に接続。
- ito-markdown を無理に編集エンジンへ拡張しない（役割が違う）。構造コマンドは新しい共通クレート `ito-mdedit` になった（下の「調べて分かったこと」）。**最初の具体化は Document Engine の内部設計**（バッファ、カーソル、選択、構造木、元に戻す、コマンド実行、IME の接続）。
- 進み具合（2026-11-02）: (1)〜(2) 済み。(3) は調べて無かったので ito に頼んだ（uchmk/ito#156）。(5) 済み（ito v0.221.0）。(6) 済み（`/new-app`、rev `73cce5b`）。次は (4)、#156 が入ったら (7)。

## 調べて分かったこと（再利用の可否）
- **ito-markdown は土台にならない。** 依存なしの行指向リーダーで、GitHub のコメント向け。`Block`/`Span` にバイト位置が無く、入れ子のリストも参照リンクも無い。バッファ・選択・元に戻す型も無い（`Writing` は egui の `TextEdit` を借りるだけ）。
  使える部品は `continue_list`（Enter でリスト継続）と `tool`（太字・見出しなどの囲み）くらい。
- **構造木は pulldown-cmark から作る。** kura の `src/preview/markdown.rs` が `Parser::new_ext(...).into_offset_iter()` で各イベントのバイト範囲を持っている（`options()` は表・脚注・取り消し線・タスク・GFM・YAML メタデータ）。同じ作りにすれば、見出し・リスト・表・コードブロックの範囲が取れる。
- **整形（`render` → `Doc`）は ito に切り出し済み（2026-11-02、`ito-mdview` v0.220.0、#151）。** `render(text, cols, &Palette)` → `Doc`。各 `DocLine` が元のバイト範囲 `bytes` と行 `src` を持ち、`Doc::line_at_byte` / `byte_at_line` で原文と整形行を行き来できる。`headings`（レベル 1〜6）、検索の `marks`、数式・図は `LineKind::Placeholder`。機能 `theme` で `Palette::from_theme()`。**egui の描画はまだ**（別の段階）。kura はまだ乗せ替え前。
- **ミニマップは切り出し済み（`ito-minimap` v0.219.0、#149）。** `Row` / `rows` / `show`（機能 `egui`）/ ホバーカード。原文の行に対して描く設計で、kura は整形した Markdown には出さず、目次の列で「今どこか」を示す。エディターでも同じ分担にする: **原文側にミニマップ、整形側に目次**。
- **目次・見出しは `ito-outline`（v0.217 / v0.218、#150）。** `headings`（段・題・バイト範囲・行・節の範囲 `section`、`at_byte`）と、右の目次の列 `column::show`（機能 `egui`）。
- **構造コマンドは切り出し済み（`ito-mdedit` v0.221.0、uchmk/ito#3）。** `move_block` / `move_section`（`Dir`）、`promote_section` / `demote_section`、`indent_item` / `outdent_item`、`toggle_task`、`renumber`、`format_table`、`next_cell`（`Step`）。
  どれも `(text, caret_byte) -> Option<Change { range, text, cursor }>` で、`Change::apply` で適用する。weft はこの `Change` を 1 回の元に戻すの単位としてトランザクションに積む。
- **色づけ**は ito-syntax。`Stream` は前方のみだが、v0.221.0 で `Clone` になった（uchmk/ito#4）。数百 KB 程度なら毎回読み直しで足り、大きなファイルでは N 行ごとに複製して保存点にする。
- **ito にあって使える部品**: ito-mdedit、ito-outline、ito-minimap、ito-mdview、ito-syntax、ito-ime（日本語入力）、ito-keys・ito-keymap・ito-keyscript（キー、テスト）、ito-palette（コマンド一覧）、ito-match（あいまい検索）、ito-select、ito-diff、ito-store（SQLite FTS5 trigram で日本語全文検索）、ito-watch、ito-openin、ito-export、ito-common・ito-prefs。
